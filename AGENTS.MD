# Инструкции для агентов: UBAS Frontend

## Назначение и порядок работы

Проект — русскоязычный интерфейс поиска авиабилетов с пересадками и остановками
в промежуточных городах. Бэкенд подбирает и ранжирует маршруты; фронтенд отправляет
параметры поиска, ожидает результат и отображает предложения.

- Перед изменениями прочитайте относящиеся к задаче исходники, тесты и `README.md`.
  Актуальные зависимости и команды определяются `package.json` и lock-файлом.
- Проверьте `git status` и сохраните существующие изменения пользователя.
- Сохраняйте структуру проекта. Не меняйте API-контракт, набор отображаемых данных
  или архитектуру состояния ради оформления интерфейса.
- О существенных неоднозначных продуктовых решениях спрашивайте пользователя.
  Обычные технические решения принимайте самостоятельно в рамках задачи.
- Пользовательские тексты и сообщения о выполненной работе пишите по-русски.
  Имена файлов, компонентов и переменных оставляйте на английском.
- При изменении архитектуры, команд или важных соглашений обновляйте этот файл
  и соответствующий раздел `README.md`.

## Стек

- React 18.2, TypeScript в строгом режиме, Vite 6, npm и `package-lock.json`.
- shadcn/ui, стиль New York, база neutral; компоненты находятся в репозитории.
- Radix (`radix-ui`), cmdk, Tailwind CSS 4 через `@tailwindcss/vite`.
- Lucide для иконок, `date-fns` и `react-day-picker` для календарей.
- Axios для HTTP; Vitest, Testing Library и Axios Mock Adapter для тестов.
- Playwright для браузерных проверок; ESLint и Prettier для качества кода.
- `react-2048@1.1.0` — игра на ожидании; запускается в отдельном локальном iframe.

Состояние сейчас хранится в React hooks. Redux, React Router, Leaflet и некоторые
другие пакеты установлены, но не подключены к приложению. Их наличие не является
основанием вводить новое хранилище, маршрутизацию или карту.

## Код и оформление

- Соблюдайте `.editorconfig`, `.prettierrc.json` и `.eslintrc.cjs`: два пробела,

- Для типов используйте `import type`; ошибки в `catch` обрабатывайте как `unknown`.
  Не добавляйте `any`, `@ts-ignore` и отключения правил вместо исправления причины.
- Сохраняйте соглашения существующего файла об импортах и экспортах. В предметном

- Не добавляйте зависимости для задач, которые уже решают установленные пакеты.
  При необходимости новой зависимости обновляйте и `package.json`, и lock-файл.
- Сохраняйте совместимость с React 18; обновление React и связанных библиотек

## UI: единая светлая чёрно-белая тема

Пользователь выбрал светлый интерфейс с чёрными и серыми акцентами. Следуйте этому
направлению при добавлении экранов и компонентов.

- Используйте существующие Button, Input, Label, Card, Badge, Alert, Dialog,
  Popover, Calendar, Select, Checkbox и другие примитивы из `components/ui`.
- Цвета, шрифт, радиусы и состояния задавайте токенами в `globals.css`.
  Предпочитайте `bg-background`, `bg-card`, `text-foreground`, `text-muted-foreground`,
  `border-border`, `bg-primary` вместо отдельных палитр и захардкоженных цветов.
- Для обычной вёрстки используйте Tailwind. Не возвращайте SCSS-модули и россыпь
  inline-стилей. Особые общие стили добавляйте в существующий слой темы.
- Для иконок используйте Lucide. Декоративные иконки скрывайте через `aria-hidden`,
  кнопкам без текста задавайте понятное доступное имя.
- Сохраняйте читаемую иерархию: время и цена заметны, метаданные вторичны,
  предупреждения собраны в компактный блок. Не скрывайте оценку маршрута или
  разбивку стоимости без соответствующей задачи.
- Проверяйте длинные названия, переносы, фокус, управление клавиатурой и отсутствие
  горизонтальной прокрутки на мобильной ширине.
- Используйте состояния загрузки, ошибки, пустой и частичной выдачи.
  Не заменяйте диалоги интерфейса браузерным `alert`.

### Особенности shadcn, Radix и cmdk

- Конфигурация shadcn находится в `components.json`. Добавление примитива:
  `npm run ui:add -- tooltip` (имя компонента замените на нужное).
- Это локальные исходники компонентов, а не закрытая тема. Проверяйте diff после
  генерации, исправляйте импорты и форматирование; сохраняйте MIT-лицензию рядом.
- У Button нужен `forwardRef` для React 18: Radix передаёт ref через `asChild`.
  Не заменяйте его версией, рассчитанной только на React 19.
- В CityAutocomplete cmdk управляет внутренним ID поля и использует его для возврата
  фокуса. Не переопределяйте этот ID. Текущая композиция `CommandInput asChild`
  сохраняет ID cmdk и задаёт связь с видимой подписью через `aria-labelledby`.
- При ручном вводе после выбора города сбрасывайте выбранный объект, сохраняя
  введённый текст. Иначе в запрос может попасть старый код города.
- При закрытии RouteDetails возвращайте фокус на кнопку, открывшую диалог.
- Закрывающиеся Popover могут кратковременно оставаться в DOM из-за анимации.
  В браузерных тестах выбирайте календарь внутри открытого Popover:
  `[data-slot="popover-content"][data-state="open"]`.

## Бизнес-правила и контракт API

### Игра во время ожидания

`WaitingGame` не управляет поиском и не останавливает polling. `2048.html` —
вторая HTML-точка входа Vite; публикуйте весь `dist/`. Пакет `react-2048`
изолирован во фрейме из-за его глобальных обработчиков клавиатуры. Фрейм
создаётся по запросу и остаётся смонтированным при скрытии, завершении,
ошибке и следующем поиске. Состояние не обещается после обновления страницы.
Проверяйте источник и origin сообщений iframe. При обновлении пакета
перепроверяйте адаптер русского текста, CSS, Tab/Escape, свайпы и размеры поля.
E2E игры должны проверять настоящее поле, продолжение polling и сохранение
партии после готовности результата; мобильные тесты отправляют touch-события.

Для `react-2048@1.1.0` обязателен `postinstall` из `scripts/patch-react-2048.mjs`:
он исправляет гонку второго хода до очистки предыдущего слияния. При обновлении
пакета пересмотрите исправление; не убирайте блокировку без проверки задержанных
таймеров и ходов без изменений. Пакет исключён из optimizeDeps для чтения
исправленного ESM напрямую. `GameErrorBoundary` должен оставлять восстановление
игры доступным, а родитель не должен обещать сохранённую партию после её ошибки.

### Города и даты

- Поиск выполняется по **городам**, а не отдельным аэропортам. В запрос передаются
  `origin.cityCode` и `destination.cityCode`: Москва — `MOW`, Токио — `TYO`.
  `SVO`, `DME`, `HND`, `NRT` не являются заменой этих городских кодов.
- Один город — одна запись в меню. Используйте `CityOption` и `data/cities.ts`.
  Отдельного API подсказок городов в предоставленном контракте нет.
- В сегментах результата сохраняются реальные коды аэропортов и `city_code`.
  При обмене направлениями меняйте выбранные объекты вместе с их кодами.
- `date_from` и `date_to` — диапазон дат вылета, а не даты вылета и обратного рейса.
  Передавайте строки `YYYY-MM-DD`; начало диапазона не должно быть позже конца.
- Текущую календарную дату вычисляйте локально, например через
  `format(new Date(), 'yyyy-MM-dd')`. Не используйте `toISOString().slice(0, 10)`:
  около полуночи дата UTC может отличаться от местной.
- Время рейса показывайте в часовом поясе соответствующего аэропорта.
  Для длительностей сравнивайте абсолютные моменты времени, учитывая ISO offset.

### Асинхронный поиск

1. `POST /api/v1/queries` → `{ query_id, status, reused }` (HTTP 202).
2. `GET /api/v1/queries/{query_id}` → статус и метаданные задачи.
3. `GET /api/v1/queries/{query_id}/result` → `{ query_id, result: PlanResult }`.

Используйте `createRoute`, `getRouteStatus`, `getRouteResult` и `waitForRouteResult`.
Статусы: `queued`, `running`, `completed`, `failed`. Результат определяется флагом
`result_available`; состояние выполнения задачи и `result.complete` имеют разный смысл.

- Сохраняйте последовательный опрос: следующий запрос статуса начинается после
  окончания предыдущего. Не возвращайте `setInterval(async ...)` с перекрытиями.
- Передавайте `AbortSignal`; отменяйте предыдущую операцию при новом поиске и при
  размонтировании. Отменённый ответ не должен обновлять состояние страницы.
- `Idempotency-Key` необязателен. Если он используется, при повторе того же запроса
  сохраняйте ключ; для другого запроса не переиспользуйте его бездумно.
- Ошибки задачи передаются в `failure`; `QueryFailedError` сохраняет эти данные.
  Для HTTP 422 показывайте сообщения конкретных полей через `getApiErrorMessage`.
- Типы Axios/TypeScript не проверяют JSON во время выполнения. Не объявляйте
  совместимость с новым контрактом без сопоставления полей и структуры ответа.

### Маршруты, билеты и деньги

Правильная структура результата:

```text
QueryResult.result: PlanResult
  routes: RankedRoute[]
    route: RouteCandidate
      tickets: TicketOffer[]
        segments: FlightSegment[]
      stopover, visa, metrics, warnings
      ticket_cost, visa_cost, total_cost
    score: RouteScore
  complete, warnings, searched_cities, evaluated_candidates, rejected, generated_at
```

- Верхнеуровневого `offers` нет. Читайте `response.result.routes`.
- `TicketOffer` — независимо покупаемый билет, а не весь маршрут.
  Для представления объединяйте сегменты всех билетов через адаптер; сохраняйте
  исходный `RankedRoute` и границы билетов для подробностей и покупки.
- Итоговая цена карточки — `route.total_cost`; отдельно доступны билеты и виза.
  `TicketOffer.total_price` уже покрывает всех пассажиров: повторно умножать её нельзя.
- Денежные суммы в API — десятичные строки. Не меняйте их на number в моделях API.
  Для вывода используйте `formatMoney`; отсутствие `Money.currency` означает RUB.
  Не задавайте символ рубля жёстко для всех результатов.
- Общее время берите из `metrics.total_trip_hours`. Сохраняйте серверный порядок
  ранжированных маршрутов, если задача явно не требует другой сортировки.
- Учитывайте необязательные и nullable-поля, особенно `booking_url`, багаж и значения
  с defaults. Не выдавайте неизвестное наличие багажа за его отсутствие.
- Ссылку покупки показывайте только при наличии корректного HTTP(S) URL.
  Для внешних ссылок в новой вкладке сохраняйте `rel="noopener noreferrer"`.

### Предупреждения

- `PlanResult.warnings` относится ко всей выдаче, `RouteCandidate.warnings` — к маршруту.
  Оба уровня отображаются через WarningList.
- Не выводите пользователю машинные коды вроде `unprotected_connection` напрямую.
  Дополняйте существующий словарь русских сообщений. Читаемый текст сервера сохраняйте.
- Сохраняйте дедупликацию, обработку неизвестных кодов и пустых массивов.
  Для `synthetic_demo_data` явно сообщайте, что предложения демонстрационные.
- `complete: false` — частичная выдача. Не представляйте её как полный результат
  и не теряйте предупреждения при пустом массиве маршрутов.

## Окружение

`VITE_API_URL` — публичная настройка адреса бэкенда, читаемая через `import.meta.env`.
Клиент принимает origin, адрес с `/api` или `/api/v1` и нормализует его до `/api/v1`.
Без настройки используется `/api/v1` текущего origin; префикс не должен дублироваться.

Локальный `.env.development` может быть не отслеживаемым Git. Не перезаписывайте
локальные настройки пользователя и не переносите в репозиторий секреты. Любая
переменная с префиксом `VITE_` попадает в клиентский код. Vite proxy сейчас не настроен;
при разных origin доступ должен разрешаться конфигурацией CORS на бэкенде.

- После изменений приложения запускайте подходящие тесты, сборку, lint и проверку
  форматирования. Для изменений взаимодействия, календарей, фокуса и адаптивности
  выполняйте также E2E. После успешных проверок не повторяйте их без новых изменений
  или нерешённых проблем.
- Для правки только документации достаточно проверки форматирования затронутых
  файлов. Не добавляйте тесты, повторяющие простую разметку или константы.
- Содержательные тесты должны защищать поведение: отправляемые коды городов,
  вложенную структуру результата, все билеты, ошибки, отмену, клавиатуру и фокус.
- Vitest ищет `src/**/*.test.{ts,tsx}`. Для DOM-тестов используется комментарий
  `// @vitest-environment jsdom`; общие адаптации браузерных API лежат в `src/test/setup.ts`.
- E2E лежат в `tests/e2e`, работают на ширинах 1280 и 390 px, с русской локалью
  и часовым поясом Asia/Yekaterinburg. Они подменяют ответы API и не требуют бэкенда.
- Playwright сам запускает Vite на `127.0.0.1:4173` с пустым `VITE_API_URL` и не
  переиспользует уже запущенный сервер. Не занимайте этот порт параллельно проверке.
- Chromium выбирается через `CHROMIUM_PATH`, системный `/usr/bin/chromium` или
  установленный браузер Playwright. Если браузера нет: `npx playwright install chromium`.
- Не коммитьте `node_modules`, `dist`, `test-results` и `playwright-report`.
  Не редактируйте артефакты сборки вместо исходников.
