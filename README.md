# UBAS Frontend

React + TypeScript + Vite + shadcn/ui: поиск авиамаршрутов с пересадками.

## Запуск и проверки

```sh
npm ci
npm start
npm run build
npm run lint
npm test -- --run
npm run test:e2e
npm run format:check
```

Docker-сборка и production deployment описаны в
[docs/deployment.md](docs/deployment.md). Локальный контейнер запускается так:

```sh
cp .env.example .env
docker compose up --build -d
```

Frontend будет доступен на `http://127.0.0.1:8080` и обращаться к локальному
backend на `http://127.0.0.1:8000`.

## Интерфейс

Используется shadcn/ui (New York), Radix, Tailwind CSS 4 и Lucide. Оформление —
светлая тема с чёрными и серыми акцентами. Общие цвета, шрифты, радиусы и состояния
задаются в `src/styles/globals.css`; индивидуальные SCSS-модули заменены компонентами
и утилитами Tailwind.

- `src/components/ui/` — исходники общих компонентов shadcn, их MIT-лицензия лежит рядом.
- `src/components/CityAutocomplete/` — выбор города на Command/cmdk, с поиском и клавиатурой.
- `src/components/DatePicker/` — Calendar и Popover с русской локалью. В API уходят строки `YYYY-MM-DD` по местной дате.
- `src/components/RouteCard/` и `RouteDetails/` — карточка и диалог с составом билетов и доступными ссылками покупки.
- `src/components/WarningList/` — перевод предупреждений сервера и их вывод через Alert.
- `src/lib/` — объединение классов и общие форматтеры. Алиас `@/` указывает на `src/`.

Структура страниц сохранена: в App подключён SearchPage, служебная страница
RouteClientTestPage и прежний ExamScreen также оформлены через общий UI.

Новый общий компонент можно добавить командой `npm run ui:add -- tooltip`.
Конфигурация registry и путей — в `components.json`. Компоненты основаны на
[официальном реестре shadcn/ui](https://github.com/shadcn-ui/ui/tree/main/apps/v4/registry/new-york-v4/ui)
и приведены к стилю проекта (2 пробела, одинарные кавычки, точки с запятой).
Для React 18 у Button сохранён forwardRef: он нужен для позиционирования Popover
и возврата фокуса. При обновлении исходников UI эту совместимость следует сохранять.

`npm run format` форматирует проект. Vitest проверяет API и интерфейс, а Playwright —
поиск, календари, диалог и отсутствие горизонтальной прокрутки на ширинах 1280 и 390 px.
В браузерных тестах ответы API подменяются: работающий бэкенд не требуется.
Используется `CHROMIUM_PATH`, системный `/usr/bin/chromium` или установленный браузер
Playwright. При отсутствии Chromium установите его командой `npx playwright install chromium`.

## Уведомление о найденных маршрутах

Во время поиска кнопка «Включить» запрашивает разрешение на системные уведомления.
Разрешение браузера действует и для следующих поисков. Вкладка должна оставаться
открытой до получения результата. Когда найдены маршруты, браузер показывает
уведомление «Маршруты найдены». Нажатие возвращает на открытую вкладку поиска.
При пустой выдаче или ошибке уведомление не появляется.

Нужны HTTPS или localhost и браузер с поддержкой Notifications API. Сайт показывает
уведомление через service worker `/route-notifications.js`, используя результат
обычного опроса API поиска.

## 2048 во время ожидания

После отправки поиска появляется кнопка **«Сыграть в 2048»**. Игра загружается
только после нажатия; статус поиска остаётся видимым, опрос API продолжается.
Когда результат готов, появляется кнопка **«Посмотреть результаты»**. Поле не
сбрасывается: игру можно скрыть и продолжить, в том числе при следующем поиске.
При ошибке запроса партия также остаётся доступной. Состояние живёт в текущей
вкладке; обновление страницы начинает новую партию.

Подключён `react-2048@1.1.0` (MIT). Его компонент запускается на локальной странице
`2048.html` внутри iframe: глобальные обработчики пакета изолированы от формы.
`src/game2048/EmbeddedGame.tsx` ограничивает стрелки фокусом игрового поля,
сохраняет работу Tab/кнопок, обрабатывает Escape и переводит подписи на русский.
Адаптер перевода и CSS проверены для закреплённой версии пакета; при обновлении
нужно перепроверять подписи, классы, фокус и свайпы.

В версии 1.1.0 исправлена гонка: следующий ход мог прийти до завершения очистки
плиток предыдущего слияния и полностью очистить React-корень игры.
`scripts/patch-react-2048.mjs` автоматически применяется через `postinstall` к
ESM/CJS сборкам установленного пакета. Он блокирует ввод до подтверждённой
очистки, включая задержанные таймеры; ход без изменений освобождает блокировку.
Скрипт идемпотентен и отказывается применять исправление к неизвестной версии.
Vite читает пакет напрямую, чтобы не использовать старую оптимизированную копию.
Для повторного применения исправления: `npm run postinstall`.

`GameErrorBoundary` сохраняет управление и показывает кнопку новой игры при
непредвиденной ошибке вместо пустого поля. Поиск продолжает работать независимо.
Регрессия проверяется с намеренно задержанной до 700 мс очисткой анимации.

Управление: стрелки на компьютере, свайпы на сенсорном экране. Свайп по полю
не прокручивает страницу; прокрутка вне поля остаётся доступной. Размер поля
адаптируется к узкому экрану. Оформление использует чёрно-белые токены UBAS.
`vite.config.ts` собирает обе HTML-страницы. В production нужно размещать весь
`dist/`, включая `2048.html`, и не перенаправлять её на основной `index.html`.

`tests/e2e/waiting-game.spec.ts` проверяет настоящее игровое поле с управляемым
ожиданием API: слияние чисел, свайп через Chrome DevTools Protocol, продолжающийся
опрос, переход к результатам, сохранение поля, ошибку поиска, Tab/Escape и ширины
390/320 px. Это эмуляция сенсорного телефона в Chromium.

## Адрес бэкенда

В `.env.development` задаётся адрес сервера:

```dotenv
VITE_API_URL=http://127.0.0.1:8000
```

Клиент добавляет `/api/v1`. Также допустим адрес, уже заканчивающийся на
`/api` или `/api/v1`: префикс не дублируется. Без переменной запросы идут на
`/api/v1` текущего origin. При таком размещении сервер или reverse proxy должен
направлять этот путь к бэкенду. При разных origin бэкенд должен разрешать CORS
для адреса фронтенда и заголовка `Idempotency-Key`, если он используется.

## API-клиент

Страница поиска сохраняет полученный `query_id` в cookie `ubas_query_id` на 7 дней
(`Path=/`, `SameSite=Lax`, `Secure` при HTTPS). При повторном открытии страницы
клиент проверяет статус сохранённого запроса и продолжает опрос до получения
результата. Новый POST при восстановлении не отправляется. В cookie хранится
только идентификатор, сами результаты каждый раз загружаются с сервера.

Кнопка «Новый поиск» удаляет эту cookie, сбрасывает результат и прекращает
локальное ожидание; серверную задачу она не отменяет. При сетевой ошибке
идентификатор сохраняется, а кнопка «Повторить загрузку» повторяет получение
данных. Если сервер больше не хранит запрос (404/410), страница предлагает
начать новый поиск.

Типы в `src/api/models.ts` соответствуют предоставленной схеме UBAS Backend 0.1.0.
Даты передаются ISO-строками, денежные суммы остаются десятичными строками.
Необязательные и nullable-поля отражены отдельно. Ограничения форматов и диапазонов
проверяет сервер; TypeScript-типы не выполняют runtime-валидацию JSON.

`src/api/route.ts` предоставляет `createRoute`, `getRouteStatus`, `getRouteResult`
и последовательный опрос `waitForRouteResult`:

```ts
import { createRoute, waitForRouteResult } from './src/api/route';

const controller = new AbortController();
const { query_id } = await createRoute(
  {
    origin: 'MOW',
    destination: 'TYO',
    date_from: '2026-11-01',
    date_to: '2026-11-02',
  },
  {
    signal: controller.signal,
    // Необязательный ключ: сохраняйте его при повторе того же запроса.
    idempotencyKey: crypto.randomUUID(),
  },
);

const { result } = await waitForRouteResult(query_id, {
  signal: controller.signal,
  pollInterval: 2000,
});
// result.routes содержит RankedRoute[], а не отдельные TicketOffer.
// controller.abort() отменяет HTTP-запрос и ожидание следующего опроса.
```

Ответ статуса сохраняет метаданные задачи и `failure`. Результат запрашивается
при `result_available`; ошибка задачи выбрасывается как `QueryFailedError`,
сохраняющий `failure.code`, `failure.message` и `failure.retryable`.
`getApiErrorMessage` форматирует сообщения HTTP 422 с путями проблемных полей.

Адаптер в `src/adapters/route.ts` сохраняет исходный RankedRoute, объединяет
сегменты всех его билетов для отображения, использует `total_cost` (включая визу),
валюту и `metrics.total_trip_hours`. Время показывается в часовом поясе аэропорта.
Интерфейс отображает пустые и частичные результаты и предупреждения сервера.

Тесты используют Axios Mock Adapter и примеры ответов по схеме, включая несколько
билетов, пропущенные optional-поля, ошибки и отмену. Они не требуют запущенного
бэкенда. В форме выбираются города через интерфейс `CityRepository`:
Москва — `MOW`, Токио — `TYO`. В запрос передаются коды городов, а не отдельных
аэропортов. В предоставленной схеме нет метода поиска городов. Аэропорты в
найденных маршрутах по-прежнему показываются с их собственными кодами.

## Каталог и поиск городов

Локальный каталог включает все 271 города из `scraper-airports-2026-11-10.json`,
а не только шесть `covered_cities` или отдельные аэропорты. В `src/data/cities.json`
хранится проекция раздела `cities`: исходные коды, английские названия, страны,
часовые пояса и русские названия всех городов. Метаданные источников и attribution
сохранены. Названия стран формируются через `Intl.DisplayNames` с локалью `ru`.
Исходный файл scraper остаётся эталоном для проверки полноты импорта.

`CityRepository` объявлен в `src/types/city.ts`:

```ts
interface CityRepository {
  search(query: string, options?: CitySearchOptions): Promise<CityOption[]>;
  getByCodes(cityCodes: readonly string[], options?: CityRequestOptions): Promise<CityOption[]>;
}
```

`CitySearchOptions` содержит `signal` и `limit` (по умолчанию 20),
`CityRequestOptions` — `signal`. `getByCodes` возвращает известные города без
дубликатов; неизвестные коды пропускаются. Публичная модель `CityOption` содержит
только `cityCode`, `cityName` и `countryName`.

- `src/services/local-city-repository.ts` — единственный потребитель формата локального
  каталога. Поиск не зависит от регистра, диакритики, вариантов `е`/`ё`, пробелов и дефисов.
  Сопоставляются русские и исходные английские имена, а также городские коды.
  Точные коды и названия приоритетнее префиксов и частичных совпадений.
- `src/services/city-repository.ts` — точка выбора реализации. Для перехода на сервер
  добавьте HTTP-реализацию того же интерфейса и замените здесь привязку. Эндпоинт
  следует выбирать по будущему контракту бэкенда; сейчас HTTP-поиск не реализован.
- `src/hooks/useCitySearch.ts` — асинхронное состояние поиска, отмена и защита от
  устаревших ответов, включая источники, которые не соблюдают AbortSignal.
- `CityAutocomplete` принимает необязательный `repository` для подмены источника.
  Он показывает загрузку, пустой результат, ошибку и кнопку повторной попытки.
  Результаты предыдущей строки не остаются доступными для выбора при новом вводе.
- SearchPage получает названия городов маршрута через `getByCodes` и передаёт их
  адаптеру. При недоступности справочника найденные перелёты всё равно отображаются
  с городскими кодами. Сам адаптер не импортирует данные и не выполняет запросы.

В запрос поиска билетов по-прежнему уходят городские коды: `MOW`, `TYO`, `LON`,
`PAR`. Аэропорты `SVO`, `HND`, `LHR`, `CDG` не создают дополнительные пункты меню.
Тесты проверяют покрытие исходного JSON, русские названия, английские алиасы,
ограничение выдачи, отмену, запоздавшие ответы и заменяемость источника.
